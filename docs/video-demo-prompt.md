# 给 Codex 的真机演示录制提示词

[返回首页](../README.md) · [短视频文案与口播](launch/zh-CN.md) · [先看界面](quick-tour.md)

把下方提示词交给**能访问你本机项目、屏幕和录屏工具的编程助手**。这是录制任务说明，仓库并不附带作者的私人招聘聊天或现成真人录屏。需要你已有可运行的软件与本人有权展示的招聘记录；没有的内容不能编造。

默认发布版遮挡个人信息。招聘平台画面只在你自己的电脑上读取；不要把聊天原文、未脱敏录屏、Cookie 或账号凭据提交到公开仓库。

```text
请在我的电脑上，为 Job Search Harness 录制一段约 2 分钟的实际使用演示，
并剪出一段 30–45 秒短版，用于介绍这个开源项目。
仓库：https://github.com/milkrabbitt/job-search-harness

先检查项目实际版本、可用入口、当前数据模式、已登录浏览器和录屏能力。
读 README、docs/candidate-guide.md、docs/compensation.md、job_harness/CHANNELS.md。
保留我已有的代码、资料与配置；不以发布演示为由触发新的申请或招聘回复。

素材与真实性：
1. 录制实际运行的软件和实际操作，不生成或重画软件界面，不拼造招聘聊天。
2. 演示数据明确标“虚构数据演示”；本人授权的真实沟通标“实际沟通记录”。
   两种素材分段呈现，不能把虚构面试邀请剪成真实求职结果。
3. 优先使用已核实的真实 BOSS 直聘和猎聘历史回复，展示与岗位相关的沟通进度。
   只查看已有记录，不代发新消息。不展示 Cookie、验证码、API Key、登录二维码。
   若没登录、缺记录或工具不能录屏，明确说明缺什么；可先完成其余可录部分，
   不宣称两平台已展示，不伪造“AI自动收到面试”的因果关系。
4. 默认遮挡姓名、手机号、邮箱、头像、公司敏感信息和本机路径。
   原片只放本机私有目录，公开成片使用脱敏副本；输出前逐帧抽查敏感画面。

约 120 秒完整版脚本：
00–10秒：先展示最直观的结果，如实际招聘回复或“待我决定”的面试事项。
         口播：“投过什么、对方回了什么、下一步做什么，放在一张工作台里。”
10–25秒：运行概览与首次配置。展示岗位方向、城市、薪资底线、模型和来源。
         说明模型由用户自备，配置通过检查后开始工作。
25–45秒：我的经历与简历。用已授权资料或虚构 PDF 展示上传、核对文字、确认经历。
         展示实际已有的匹配点与依据；模型未连接时不伪造输出。
45–60秒：岗位与薪资对比。选择 2–3 个岗位，突出原报价、明示薪数和待确认项。
60–85秒：实际 BOSS、猎聘沟通记录。各展示一段本人授权的已有岗位回复，
         标清这是原平台的人工浏览器操作；仅有一个平台时如实调整脚本。
85–105秒：招聘消息、草稿与发送、待我决定。解释哪些是同步记录、哪些是手动登记。
          已授权126邮件可以按规则处理常规请求；面试和谈薪由本人决定。
105–115秒：资料与设置、执行日志、暂停入口。快速展示数据位置和任务控制。
115–120秒：仓库首页与安装提示词。
          口播：“已经开源。先跑不用账号的演示，觉得有用就点个 Star 留着。”

剪辑与交付：
- 原录屏按屏幕原生分辨率或清晰的 1080p 横版保存，不把宽界面强压成竖屏。
- 另导出 1080×1920 竖版，以实际画面放大/裁切配字幕；确保关键操作和字可读。
- 短版用“结果 → 如何做到 → GitHub与安装”的顺序，只保留3个重点。
- 每个关键界面至少停留到能看清，鼠标动作自然，不使用假加载或假成功状态。
- 口播与画面能力一致，不说全平台无人值守、保证offer、完全免费或绝不上传数据。
- 先提供时间轴与已录素材检查，再输出完整版、短版、字幕SRT、封面帧和口播文本。
- 检查视频总时长、分辨率、音画同步、字幕安全区与敏感信息遮挡。
  报告实际覆盖的界面和平台，以及哪些场景尚未录到。
```

发布文案可使用[这里的短帖和口播](launch/zh-CN.md)。有真实效果再展示具体结果；单次案例也不代表任何用户都能获得同样结果。
