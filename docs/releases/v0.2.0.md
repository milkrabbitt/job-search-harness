# v0.2.0 · 从「下载源码」到「接好模型，开始工作」

**把找工作的下一步，交给一个记得住进度的助手。**

Job Search Harness 现在有了完整的首次配置流程：填写自己的求职目标，接入自己的模型，添加招聘来源，测试连接，再启动第一轮扫描。设置在哪里、为什么没运行、下一步缺什么，都能在本机控制台看到。

这是一个开源预览版。它把岗位来源、筛选依据、模型建议、申请草稿与人工确认放在同一个工作台里，让求职过程可以检查、暂停和继续。

## 这次真正补上了什么

- **自己的模型，自己的选择。** 内置 OpenAI、Claude、Gemini、DeepSeek、通义千问、Kimi、智谱 GLM、MiniMax 的 API 配置入口；支持本机 Codex CLI、Ollama、LM Studio，以及自定义 OpenAI 兼容接口。模型 ID 由你填写，连接测试会检查当前账号与模型是否真的可用。
- **先配置，再开工。** 新安装默认等待配置。目标、来源与模型检查通过后，立即安排首轮岗位扫描；也可以明确选择不调用模型的规则模式。
- **求职目标属于你。** 新用户默认通用筛选，按自己填写的方向、城市、薪资底线和排除项判断。销售、算法、独立编码等要求不会因为作者的个人偏好被自动排除。
- **简历和经历有明确入口。** 在向导中填写本人确认的经历、登记自己电脑上的 PDF 简历，文件复制到私有数据目录。没有这些材料仍可扫描岗位；生成申请时会等待必要资料。
- **知道模型用了多少。** 保存配置不调用模型；测试使用虚构样例。每日调用数和单次输出长度有硬限制，失败不会悄悄换模型或无限重试。更换配置或密钥后需要重新验证。
- **启动过程覆盖三种系统。** macOS / Linux 使用 shell 脚本，Windows 使用 PowerShell；诊断会检查 Python、SQLite、时区、数据目录和本机端口。

## 两种开始方式

先看效果：运行完全离线的虚构演示；演示不会连接招聘账号或调用模型。

直接配置自己的助手：从本版本的源码开始，按[安装说明](https://github.com/milkrabbitt/job-search-harness/blob/v0.2.0/docs/install.md)运行初始化与本机服务，然后打开控制台的「开始配置」。不必先手改 JSON。

也可以把下面这段直接交给自己电脑上的编码助手：

```text
请安装 https://github.com/milkrabbitt/job-search-harness 的 v0.2.0。
先阅读仓库 README 和 docs/install.md，检查我的系统、Python、SQLite、时区和端口。
在独立目录安装，保留已有数据；先运行离线演示和测试，再初始化我的私有配置。
打开本机 /setup 页面，引导我填写真实求职目标、招聘来源和本人确认的资料。
让我在本机填写自己的模型供应商、模型 ID 与凭据，不把密钥发到聊天或 GitHub。
测试当前模型连接后，启动岗位扫描与筛选，展示首轮任务的实际结果。
遇到登录、密钥或真实个人资料缺失时让我补充，不能编造。
申请和邮件外发保持暂停，等我核对后单独开启。
```

## 使用前说清楚

模型接入经过协议、异常处理和本机 HTTP 集成测试；每个用户的真实 API 账号、区域权限与具体模型仍需在自己的电脑上测试。聊天产品会员不等于 API 额度。本地模型服务需要先由用户安装并加载模型。

本版本中的模型负责基于有限匹配特征给出复核建议，不会自动读取整台电脑、原始聊天或简历全文。使用云模型时，这些特征会发送给选择的供应商。可选保存的 API Key 是本机私有文件，**不是加密保险箱**，数据库备份不包含密钥。

启动的是来源扫描、筛选和有条件的模型复核；申请与邮件外发保持暂停。部分招聘页面需要登录或脚本渲染，不能保证自动解析。BOSS／鱼泡等站内操作仍需人工接管；现有 126 邮箱和猎聘凭据集成依赖 macOS。电脑休眠或进程退出后任务不会继续运行。

## 验证与反馈

发布流程在同一提交的自动化测试通过后才创建本版本；测试矩阵覆盖 Linux Python 3.9 / 3.12、macOS Python 3.12 和 Windows Python 3.12。测试使用虚构资料与隔离服务，不向招聘方发送消息。
